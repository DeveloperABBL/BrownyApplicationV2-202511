💳 Checkout Flow

ตะกร้า → GET /cart/summary (preview) → POST /checkout/confirm → ชำระเงิน
Flow ใหม่: ไม่มี draft อีกต่อไป — กด Back จากหน้า summary = ยกเลิกฝั่ง client ไม่ต้องเรียก API

กฎการชำระ:

  • coin, tp_wallet หรือ final_price = 0 → ชำระทันที, ล้างตะกร้า, ตัดสต็อก
  • วิธีอื่น → คืน payment_url + response_payload.qrcode/wechat สำหรับ render QR
URLคำอธิบาย
{APP_URL}/pay/browny-shop/{payment_ref}Payment web page
{APP_URL}/api/payment/browny-shop/qr/{payment_ref}QR API
{APP_URL}/api/payment/browny-shop/status/{PAYMENT_REF}Poll status (no auth)

⏳ Pending Payment ต่อลูกค้า เพิ่มใหม่

ใช้เมื่อ app เปิดใหม่และไม่มี order_id ใน memory — ดึง order รอชำระล่าสุด 1 รายการต่อ customer

GET/browny-shop/pending-payment?customer_id={CUSTOMER_ID}
bash
curl -X GET "{BASE}/browny-shop/pending-payment?customer_id={CUSTOMER_ID}" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Accept: application/json"
200 ไม่มี order รอชำระ
json
{ "success": true, "data": { "has_pending": false } }
200 มี order รอชำระ
json
{
  "success": true,
  "data": {
    "has_pending": true,
    "order_id": "c3d4e5f6-a7b8-9012-cdef-345678901234",
    "payment_ref": "202605301234567",
    "status": "pending_payment"
  }
}

กฎธุรกิจ

  • เลือก order ที่ status = pending_payment และ payment_status = pending
  • เรียง requested_at → created_at จากใหม่ไปเก่า — คืนเพียง 1 รายการ
  • order หมดอายุ (expires_at ผ่านแล้ว) → has_pending: false
  • หลังได้ order_id → เรียก GET /checkout/{order_id}?customer_id=... เพื่อดึง QR เต็ม

Flow แนะนำ

เปิด app → GET /pending-payment?customer_id= → has_pending = false → หน้าปกติ → has_pending = true → GET /checkout/{order_id}?customer_id= → แสดง QR จาก response_payload.qrcode

🧾 Receipt แก้ไข

GET/browny-shop/orders/{ORDER_ID}/receipt
bash
curl -X GET "{BASE}/browny-shop/orders/{ORDER_ID}/receipt" \
  -H "Authorization: Bearer {TOKEN}" \
  -H "Accept: application/json"

Fields ใหม่ (30 พ.ค.)

Fieldคำอธิบาย
lucky_noเลขนำโชค 1–99 (สุ่มตอนชำระสำเร็จ)
lucky_imageURL รูป {APP_URL}/images/lucky_no/{lucky_no}.png
qr_imageURL QR code {APP_URL}/storage/qrcodes/{ORDER_ID}.png
review_scoreคะแนนรีวิว (null = ยังไม่เคยรีวิว)
bonusBrowny Coin โบนัสที่ได้รับ
Order เก่าที่ paid แล้วแต่ยังไม่มี lucky_no จะถูก backfill ตอนเรียก receipt ครั้งแรก

Fields ใหม่ (31 พ.ค.) เพิ่ม

ไม่ breaking ฟิลด์เดิม — เพิ่มเข้ามาเพื่อให้ receipt แสดงสถานะ/รีวิว/โบนัสได้

Fieldคำอธิบาย
review_scoreคะแนนรีวิว (null = ยังไม่เคยรีวิว)
bonus / items[].bonusBrowny Coin โบนัส (รวม + ต่อบรรทัด)
status, status_label, status_stepsสถานะ + stepper (ordered/paid/shipping)
tracking_numberเลขพัสดุ
created_at, shipped_at, delivered_at, delivery_dateไทม์ไลน์ออร์เดอร์
payment_methodkey string (เพิ่มจากเดิมที่มี payment_channel/payment_display)

🔁 Migration Guide

เดิมใหม่
POST /checkout/draft → PATCH /{id} → POST /{id}/confirm POST /checkout/confirm ครั้งเดียว
POST /cart/summary GET /cart/summary?customer_id=... (เป็นหลัก)
ดึง QR จาก payment page URL ใช้ response_payload.qrcode จาก confirm response
GET /checkout/{id} ไม่ต้องส่ง customer_id ต้องส่ง ?customer_id= และใช้กับ pending_payment เท่านั้น
ไม่มี endpoint เช็ค pending order GET /pending-payment?customer_id= — ใช้ตอน app เปิดใหม่
